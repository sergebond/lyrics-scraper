# lyrics-scraper — инструкция для агентов

## Что это

**Склад песен.** Чёрный ящик: на вход — имя исполнителя (и сколько песен
нужно), на выход — текстовый файл с текстами и аккордами в фиксированном
формате. Как склад работает внутри (какие сайты опрашивает, как их парсит,
в каком порядке перебирает) — не твоя забота и не часть контракта.

**Не заглядывай внутрь `src/`.** Тебе не нужно знать, что там cheerio,
регулярки, HTML-парсинг конкретных сайтов и т.п. Обращайся только к двум
точкам входа ниже (`scrapeArtist`/`buildOutputFile` как модуль, или CLI) —
это единственный контракт, на который можно полагаться. Реализация внутри
может измениться в любой момент, сигнатура входа/выхода — нет.

Если тебе кажется, что нужно открыть файл внутри `src/sources/` — скорее
всего это неверный путь: то, что тебе нужно, уже выражается через параметры
`scrapeArtist` (см. ниже). Если параметров не хватает — предупреди
пользователя/попроси добавить, а не лезь чинить/расширять источники сам.

## Контракт (это всё, что нужно знать)

### Вход

```ts
interface ScrapeOptions {
  artist: string;              // имя исполнителя, любой язык — "ДДТ", "Metallica", "Shakira"
  count?: number;               // сколько самых популярных песен взять; по умолчанию 20
  songs?: string[];             // ИЛИ: конкретная песня/список песен по названию, вместо top-N
  source?: "amdm" | "mytabs" | "guitaretab" | "lacuerda"; // форс источника; обычно не нужен
  onProgress?: (message: string) => void; // необязательный коллбек статуса
}
```

Склад сам решает, откуда доставать песни. Не указывай `source`, если
пользователь явно не попросил конкретный сайт.

### Выход

```ts
interface ScrapeResult {
  artist: string;      // что запросили
  source: string;       // откуда фактически приехало (справочно, не для логики)
  songs: Song[];         // Song = { title, artist, key, url, body }
  notFound: string[];    // какие из songs не нашлись (пусто, если брали top-N)
}
```

`buildOutputFile(result.songs)` — собирает `songs` в единый `.txt` в формате
склада (см. «Формат файла» ниже). Больше ничего гарантировано не форматируется —
если нужен другой формат/структура, преобразуй `songs` сам, а не трогай
внутренности склада.

### Только список песен, без текста и аккордов

Если нужно узнать, какие песни вообще есть у исполнителя (названия), а не
скачивать их текст — используй `listSongs`, а не `scrapeArtist`. Она не
трогает страницы отдельных песен, только страницу исполнителя — быстрее и
не тянет лишнего:

```ts
interface ListSongsOptions {
  artist: string;
  count?: number;    // не задано — вернутся все найденные песни
  source?: "amdm" | "mytabs" | "guitaretab" | "lacuerda";
  onProgress?: (message: string) => void;
}

interface ListSongsResult {
  artist: string;
  source: string;
  songs: { title: string; url: string; views: number }[]; // без text/аккордов
}
```

```ts
import { listSongs } from "lyrics-scraper";

const { songs } = await listSongs({ artist: "ДДТ" }); // все песни, только метаданные
```

На acordes.lacuerda.net у `views` нет реального смысла (сайт не публикует
ни просмотры, ни рейтинг) — там это просто порядок на странице исполнителя.
Не строй логику на сравнении `views` между разными исполнителями/источниками.

### Ошибки

Если исполнителя не нашли **нигде** — `scrapeArtist` бросает `Error` с
человекочитаемым сообщением. Оборачивай вызов в try/catch, если исполнитель
может оказаться неизвестным. Пустой `songs` в результате (без исключения)
означает: исполнителя нашли, а конкретные запрошенные песни (`options.songs`)
— нет (смотри `notFound`).

## Как вызвать

### Как модуль (предпочтительно для интеграции в Next.js/другой проект)

Самый короткий путь — один вызов, сразу текст, ничего не пишется на диск:

```ts
import { getSongsText } from "lyrics-scraper";

const text = await getSongsText({ artist: "Земфира", count: 10 }); // строка
```

Если нужны ещё и метаданные (реальный источник, ненайденные песни) —
разбей на два вызова:

```ts
import { scrapeArtist, buildOutputFile } from "lyrics-scraper";

const result = await scrapeArtist({ artist: "Земфира", count: 10 });
const text = buildOutputFile(result.songs); // то же самое, что вернул бы getSongsText
// result.source, result.notFound — метаданные
```

`getSongsText` — это ровно `scrapeArtist` + `buildOutputFile`, ничего
больше. Ни одна из трёх функций (`getSongsText`, `scrapeArtist`,
`buildOutputFile`) не трогает диск — запись файла есть только в CLI
(`-o/--output`, см. ниже).

Работает только на сервере (Route Handler, Server Action, обычный
Node-скрипт) — делает исходящие HTTP-запросы, в клиентский компонент не тащи.

Next.js Route Handler:

```ts
// app/api/songs/route.ts
import { getSongsText } from "lyrics-scraper";

export async function POST(req: Request) {
  const { artist, count } = await req.json();
  const text = await getSongsText({ artist, count });
  return new Response(text, {
    headers: { "Content-Type": "text/plain; charset=utf-8" },
  });
}
```

### Как CLI (для разового запроса / ручного теста / без своего кода)

```bash
npx tsx src/cli.ts --artist "Metallica" --count 5
npx tsx src/cli.ts --artist ddt --songs "Дождь" "Метель"
npx tsx src/cli.ts --artist ddt --count 5 --output my_file.txt
npx tsx src/cli.ts --artist ddt --count 5 --stdout          # текст в stdout, файл не создаётся
npx tsx src/cli.ts --artist ddt --count 5 --stdout > out.txt # то же самое, просто перенаправили сами
npx tsx src/cli.ts --artist ddt --list                       # только список названий, без скачивания
npx tsx src/cli.ts --artist ddt --list --count 10 --stdout
```

По умолчанию результат — файл `<slug>_songs.txt` (или указанный через
`--output`) рядом, в том же формате, что и `buildOutputFile`/`getSongsText`.
С флагом `--stdout` файл не создаётся вообще: текст идёт в stdout, а весь
прогресс — в stderr (чтобы stdout оставался чистым текстом и его можно было
пайпить дальше).

## Формат файла (что получит пользователь)

```
Название: <название>
Исполнитель: <исполнитель>
Тональность: <аккорд или пусто>
Источник: <url>

<текст с аккордами>
========================================
Название: <следующая песня>
...
```

Ровно 40 знаков `=` между песнями, UTF-8/LF, без табов и скобок вокруг
аккордов. Это выходной контракт — не пытайся его "улучшить" своей
пост-обработкой, склад уже это гарантирует.

## Правила для агента

1. Не открывай и не редактируй `src/sources/*`, `src/textFormat.ts` и
   остальную реализацию без явной просьбы пользователя — это не API.
2. Не пытайся угадать/захардкодить, с какого сайта придёт результат — поле
   `source` в ответе информативное, не используй его в условной логике
   вызывающего кода.
3. Не проси у пользователя URL страницы конкретной песни — склад сам ищет
   и резолвит исполнителя по имени.
4. Если нужно скачать конкретные песни, а не топ-N — используй `songs`, а
   не пытайся сам фильтровать результат `count`.
5. Не выводи содержимое `body` (текст+аккорды) в чат построчно без нужды —
   отдавай файл пользователю как артефакт/вложение, а не вставляй текст
   песни в сообщение.
6. Если пользователь просит просто узнать/показать, какие песни есть у
   исполнителя (без скачивания) — используй `listSongs`, а не `scrapeArtist`
   с большим `count`: она быстрее (не ходит по страницам отдельных песен) и
   явно сигнализирует намерение «только список».
